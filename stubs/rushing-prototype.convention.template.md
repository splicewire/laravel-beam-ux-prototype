> **The mechanism is a package, not copied-in code.** This convention is a host-bound instance of the
> canonical template shipped by **`@splicewire/beam-ux-prototype`**. "Stand up prototyping in a repo"
> means *install the package + wire the one-line router glob + define the CSS token contract + scaffold
> a host `nav.ts` + first stub* — not copy runtime between repos. The authoring principles below are the
> stable conformance profile; the runtime that enacts them lives in the package.

## Profile

A prototype under `{{PROTOTYPE_DIR}}/` declares itself by carrying, at minimum:

- **`PROTOTYPE — throwaway. Do not ship.` header** *(required)* — a top-of-file block comment naming
  the originating ticket, so any reader instantly knows its status and provenance. State the design
  question the prototype answers and, if variant'd, what each `?variant=` fork means.
- **Read-only `@/` imports of real components** *(required)* — imports from `@/components/*`,
  `@/features/*`, `@/frame/*` (and real helpers) but **never edits them**. On-brand by construction.
  Nothing outside `{{PROTOTYPE_DIR}}/` imports from a prototype. Reuse shipped idioms **verbatim** where
  they exist rather than re-inventing markup.
- **Colocated fixtures** *(required)* — data lives in the effort's `<effort>/_fixtures/`, typed against
  the **real** client contracts (the `App.Data.*` DTO aliases exported from a feature's `api.ts`) so the
  prototype renders the exact shapes with no backend and no login.
- **A DEV-only route — AUTO-DISCOVERED, no per-prototype router edit** *(required mechanism, zero
  authoring cost)* — the mechanism is the **`@splicewire/beam-ux-prototype`** package. The host router
  writes ONE line inside its `import.meta.env.DEV ? [...] : []` spread —
  `...createPrototypeRoutes(import.meta.glob('{{PROTOTYPE_DIR relative}}/**/*.tsx'))` — and the package
  carries the rest: the recursive discovery (skipping `_`-prefixed dirs), the flat-slug parse, the
  `*Prototype`-or-default lazy resolve, and the auto-mounted `/_prototype` gallery index. The
  `import.meta.glob` is a Vite compile-time macro and **must stay at the host call site** (the
  load-bearing seam); everything around it lives in the package. The **slug stays flat** (filename minus
  an optional `ar`/ticket-number prefix), so moving a file into a `<effort>/` subdir never changes its
  route; keep slugs unique across efforts. The module must export a `*Prototype` component or a default.
  **Authoring a prototype never touches the router** — dropping the `<effort>/<NN>-<slug>.tsx` file IS
  the wiring. This deliberately removes the shared-file edit that races concurrent sessions on a branch.
- **`?variant=` switcher** *(optional)* — a floating variant bar + ←/→ cycling when the design has
  structural forks worth comparing side-by-side (rival layouts, permission tiers) on one route.

## Structure

- **Directory boundary — one subdir per effort.** A session/effort's prototypes live together under
  `{{PROTOTYPE_DIR}}/<effort>/`, each `<NN>-<slug>.tsx` beside its own colocated `<effort>/_fixtures/`,
  so the tree never becomes a flat junk drawer. The discovery glob is recursive, so subdir placement is
  free (the route slug stays flat). The generic throwaway chrome (`Gallery`, `VariantBar`,
  `SettingsFrame`, `PrototypeDesk` + `Crumb`) is shipped by **`@splicewire/beam-ux-prototype`**;
  `{{PROTOTYPE_DIR}}/_chrome/` holds only the host-owned remainder — the `nav.ts` rail/settings DATA and
  thin brand/nav-injecting wrappers over the packaged components (the brand wrapper injects
  `{{BRAND_IMPORT}}`). It and any `_`-prefixed dir are excluded from discovery. The whole tree is
  deliberately **separate** from any *permanent* dev harnesses and is bulk-deletable without touching
  permanent code.
- **Two fidelity tiers, chosen per prototype.** *Standalone* (default): real components + fixtures, no
  backend. *In-shell* (high-fidelity): mount inside the real app shell via a dev login against a seeded
  tenant, for surfaces whose point is the shell/nav/IA framing.
- **Route placement — automatic.** There is nothing to add: the `import.meta.glob` discovery mounts the
  file on sight. The router is edited exactly ONCE (to install the glob), never again per prototype.

## Behavior

- **Prod-exclusion is the one hard seam.** The read-only rule and directory boundary are advisory. The
  single machine-checked invariant is that prototypes never ship: run `npm run verify:prod-boundary`,
  which invokes the packaged **`verify-prototype-boundary`** CLI (from `@splicewire/beam-ux-prototype`).
  It builds the production bundle and fails loudly if `_prototype` code or a `/_prototype/` route leaks,
  catching a shipped module importing a prototype or the `import.meta.env.DEV` guard being removed.
- **The `PrototypeDesk` CSS token contract.** The desk shell ships no stylesheet — it references
  host-defined CSS custom-property tokens by classname (ADR-0116 Tailwind rule). The host **must** define
  them in its own `:root`: `--sidebar-deep`, `--sidebar-foreground`, `--sidebar-active-foreground`,
  `--sidebar-accent`, `--sidebar-primary`, `--sidebar-avatar`, `--dotted-dot` (+ the `dotted-bg`
  utility). See the package README for the full table.
- **Promotion path — this convention composes UPSTREAM of rehome-ui.** A prototype *nominates* a
  component shape; it does not decide where the real component lives. When a prototyped surface graduates
  to shipped, the **rehome-ui convention + ADR-0116** govern where it lands and its four-kind injection
  contract. What graduates: the component composition + interaction model. What stays fixture-only: the
  `_fixtures/` data and the prototype file itself (deleted, not rehomed). **Promotion completes only once
  the nominated component is _storied_** (its colocated Storybook `*.stories.tsx`): delete the prototype
  **after** its components are storied — the story is what survives, not the prototype.
